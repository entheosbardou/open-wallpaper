# Open Wallpaper — self-hosted server (alpha v0.3.0)

A single-container wallpaper media and scene manager, designed for independent self-hosting. **This is an alpha v0.3.0, not a complete cross-platform wallpaper engine.** An experimental Android client is included under `android/`; Windows/Linux clients and web-layer rendering are not implemented yet.

## Easiest install (after the maintainer publishes the GHCR image)

1. Download `compose.yaml`.
2. Replace `REPLACE_WITH_GITHUB_OWNER` with the publisher's GitHub username or organization.
3. Run `docker compose up -d`.
4. Open `http://localhost:8080` on the Docker host and create your admin account.

On another computer, use `http://SERVER-LAN-IP:8080` (replace with the server's LAN IP). Do not publish port 8080 to the public internet without HTTPS and appropriate reverse-proxy protections.

**Until a public GHCR image exists**, build locally instead:

```bash
docker compose -f compose.yaml -f compose.build.yaml up -d --build
```

Docker Compose creates one persistent named volume (`wallpaper-data`) holding the database and uploads. Back up that volume before upgrading. To stop: `docker compose down` (do not add `-v` unless you intend to delete your data).

## What works today

- First-run admin registration and password-based sign-in.
- Multi-select and drag-and-drop batch image/video uploads (100 MB maximum per file), progress per file, search, filters, selection and bulk deletion.
- Playlists with configurable media selection, interval and shuffle, plus manual browser preview.
- Scene editing with reorderable layers, opacity, save/update/delete and browser preview.
- Layered image/video/clock scenes with a visual editor and portable JSON scene manifests.
- Pairing-code API, admin approval, per-device tokens, scene assignment and revocation.
- Device configuration and authorized media download endpoints.
- GitHub Actions workflow for versioned multi-architecture GHCR images.

## What's not implemented yet

- Prebuilt Android APK and verified device playback, Windows/Linux clients.
- Actual video composition on device, animation effects, executable web widgets, and client-side clock rendering.
- QR code pairing UI, media transcoding, external object storage, account recovery.
- Automatic database migrations beyond initial schema, robust production hardening.

The dashboard currently approves pairing codes generated by API clients; no client application is bundled yet.

## Device API for future clients

1. `POST /api/pairing` with `{"name":"My tablet"}` returns a code valid for 10 minutes.
2. The admin enters that code in the dashboard.
3. `POST /api/pairing/claim` with `{"code":"..."}` returns `{"pending":false,"token":"..."}` once approved. Treat the token as a secret.
4. `GET /api/device/config` with `Authorization: Bearer <token>` returns the assigned scene.
5. `GET /api/device/media/<media_id>` with the same header returns media belonging to the assigned scene.

The scene format is **provisional**: `schemaVersion`, `id`, `name`, `canvas`, `layers`. A media layer uses `type` (`image` or `video`), `media_id`, `zIndex`. Clients should ignore unsupported layer types rather than crash.

## Publishing from your own GitHub repository

1. Create a public GitHub repository and upload the project files, preserving `.github/workflows/docker-publish.yml`.
2. Update `compose.yaml` with your repository owner's name.
3. Push a tag like `v0.3.0`. The GitHub Actions workflow builds and pushes `ghcr.io/<owner>/open-wallpaper:v0.3.0` and `:latest` for AMD64 and ARM64.
4. In GitHub package settings, make the GHCR package **public** so users can pull without signing in.
5. Publish `compose.yaml` as an easy-to-find release download.

The GitHub repository can be public without automatically making its GHCR package public.

## Security notes

Admin login uses scrypt-hashed passwords and HTTP-only same-site cookies. Device tokens are stored hashed. The app has no HTTPS termination built in; use a trusted LAN or a properly configured HTTPS reverse proxy before remote access. There is no password reset yet, and arbitrary web content is deliberately disabled until sandboxing is implemented. Uploaded file types are checked by extension, not verified by inspecting their bytes; do not expose this alpha to untrusted users. Pairing codes are bearer secrets; share them only with devices you trust.

## Version 0.3 notes

The browser scene preview is an editor preview, **not** a device wallpaper renderer. Playlist rotation/shuffle settings are saved but there is no Android client yet to play them. Batch uploads are sent as up to three concurrent requests and each file is capped at 100 MB. Deleting media currently does not automatically repair scenes or playlists referencing it; review those after bulk deletion.

This alpha is intended for trusted local networks. Do not expose it publicly without additional security work, including HTTPS, CSRF protections, upload content validation and production security review.


## Android client (experimental)

Android source is included in `android/`. To build a debug APK on GitHub, open **Actions → Android APK → Run workflow**, then download the `open-wallpaper-debug-apk` artifact. The workflow uses `android/` as its build directory. This APK has not been compiled or tested on a device here.

See `android/README.md` for connection and pairing instructions. The Android renderer is preliminary; not every dashboard scene type or playlist feature is supported.
